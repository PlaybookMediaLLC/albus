### Environment notes

This run used a Linux cloud container, not the macOS setup in the brief:

- Docker Hub refused the `pgvector/pgvector:0.8.7-pg16` pull (HTTP 429). PostgreSQL 16 with pgvector 0.6.0 ran locally on port 54480 instead, and `pnpm dev:demo` ran unchanged with a stand-in `docker` command that reports that database as the healthy container. Use `psql -h 127.0.0.1 -p 54480` where the brief says `docker exec kaneo-demo-postgres psql`.
- The demo has no object storage, so screenshot uploads would fail. A local S3 emulator (`s3rver`, outside the repository) served `S3_ENDPOINT=http://127.0.0.1:4590` for this run.
- `pnpm dev:demo` does not build `packages/widget`. Until `pnpm --dir packages/widget build` ran, `sdk.js` and the iframe page answered 503 (gap B-10).
- The API allows 10 anonymous widget sessions per hour per client IP. Repeated runs from one IP hit 429, so the driver clears that one rate bucket before each negative check. Real visitors behind one NAT share this budget (risk noted in the gap plan).

```bash
QUILLS_TEST_DATABASE_URL=postgresql://kaneo:PASSWORD@127.0.0.1:54480/quills_widget_e2e pnpm exec vp test run --config src/quills/test/vitest.config.ts src/quills/widget/widget-records.test.ts
```

It identifies a visitor and checks that the post (with metadata), vote and unvote, comment, follow, conversation and reply, help article feedback and changelog reaction all belong to that person, with `post.created`, `comment.created`, `conversation.created` and `message.created` in the outbox. It also checks the four bad tokens (403, no customer created), that one person and an anonymous session cannot read another person's conversation, that an identified session cannot be merged as an anonymous one, and that a blocked person cannot identify. The Phase 4 tests add company and trait claims, the activity feed, the updates subscription, a hidden request, AI titles, away replies, IP blocks, the REST conventions, typo search, spam, sensitive text and image holds, and the customer agent (with a stub AI provider).

- AI paths in a browser (`/widget/kb-ask`, AI titles, image checks, the customer agent and its feedback card): AI is off in the demo. Integration tests cover them with a stub provider.
- Reply by email to a post notification (G-27): needs a signed inbound-mail webhook and domain. `signed.test.ts` covers the address and the comment.
- CSAT and typing indicators: not in the widget UI that this run reached.
