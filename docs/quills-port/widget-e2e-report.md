## Setup

- Host app: `http://127.0.0.1:5290`. `/` embeds the widget with `useQuillsInit`; `/script` uses the script tag only. Its server function signs the identify token with the widget secret from the app's git-ignored `.env`. The secret came from `POST /api/quills/quills_portal_demo/settings/widget/secret` as the demo teammate (it was `null` before).
- Stack: `pnpm dev:demo` (API `127.0.0.1:1390`, web `127.0.0.1:5190`, workspace `quills_portal_demo`).
- Users: Ada (`sub` `host-ada`, `plan` = `pro`, segment `beta-program`), Grace (`host-grace`), Linus (`host-linus`), and anonymous.
- Workspace changes for the test, through teammate routes: the Help tab turned on (`PUT /settings/widget`), and a `plan` user attribute definition (`POST /user-attributes`). The seed already has the manual segment `beta-program`.

### Environment notes

This run used a Linux cloud container, not the macOS setup in the brief:

- Docker Hub refused the `pgvector/pgvector:0.8.7-pg16` pull (HTTP 429). PostgreSQL 16 with pgvector 0.6.0 ran locally on port 54480 instead, and `pnpm dev:demo` ran unchanged with a stand-in `docker` command that reports that database as the healthy container. Use `psql -h 127.0.0.1 -p 54480` where the brief says `docker exec kaneo-demo-postgres psql`.
- The demo has no object storage, so screenshot uploads would fail. A local S3 emulator (`s3rver`, outside the repository) served `S3_ENDPOINT=http://127.0.0.1:4590` for this run.
- `pnpm dev:demo` does not build `packages/widget`. Until `pnpm --dir packages/widget build` ran, `sdk.js` and the iframe page answered 503 (gap B-10).
- The API allows 10 anonymous widget sessions per hour per client IP. Repeated runs from one IP hit 429, so the driver clears that one rate bucket before each negative check. Real visitors behind one NAT share this budget (risk noted in the gap plan).


```bash
QUILLS_TEST_DATABASE_URL=postgresql://kaneo:PASSWORD@127.0.0.1:54480/quills_widget_e2e pnpm exec vp test run --config src/quills/test/vitest.config.ts src/quills/widget/widget-records.test.ts
```

It identifies a visitor and checks that the post (with metadata), vote and unvote, comment, follow, conversation and reply, help article feedback and changelog reaction all belong to that person, with `post.created`, `comment.created`, `conversation.created` and `message.created` in the outbox. It also checks the four bad tokens (403, no customer created), that one person and an anonymous session cannot read another person's conversation, that an identified session cannot be merged as an anonymous one, and that a blocked person cannot identify.
